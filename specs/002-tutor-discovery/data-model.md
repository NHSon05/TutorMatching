## Transitions

- DRAFT or REJECTED → PENDING_REVIEW only through explicit valid submission.
- PENDING_REVIEW → APPROVED, DRAFT (REQUEST_CHANGES), or REJECTED through admin review.
- APPROVED core edit → PENDING_REVIEW if complete, otherwise DRAFT; approvedAt cleared and profile hidden immediately.
- Pending tutor edits return 409; duplicate/stale submissions or reviews do not duplicate history/notifications.
- Core: display name, bio, qualification, experience, achievements, subjects/levels, rate, modes and area. Availability/course edits do not trigger profile review.
- Account deactivation hides profile without changing its approval state. Public eligibility additionally requires at least one active subject.

## Persistence and migration

Add version, normalized name, modes/area as necessary after inspecting existing mappings; do not duplicate existing columns. Index status/profileId, account status, subject associations, level associations, session rate and tutor/day schedule. Review query plans before adding further indexes.

Migration preserves original onboarding JSON/text, maps only explicit recognized catalog values and flags unresolved records for correction; research R4/R6 defines visibility handling. Seed is idempotent and versioned. Rehearse migration on a disposable database containing legacy approved/draft/incomplete-course examples; report counts before/after. Rollback requires reviewed backup restoration if normalized data has since changed; do not promise lossless automatic downgrade.

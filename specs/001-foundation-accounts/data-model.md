# Data Model: Foundation and Accounts

This feature uses ASP.NET Core Identity tables for credentials, roles, claims, recovery tokens, and
security stamps. The entities below describe project-visible semantics rather than duplicating every
framework column.

## UserAccount

Represents one registered person and authentication identity.

| Field             | Type      | Required | Rules                                               |
| ----------------- | --------- | -------- | --------------------------------------------------- |
| `Id`              | UUID      | Yes      | Primary key; generated by server                    |
| `Email`           | Text      | Yes      | Unique after normalization; valid email syntax      |
| `NormalizedEmail` | Text      | Yes      | Unique index; never public                          |
| `PasswordHash`    | Text      | Yes      | Framework-produced; never returned or logged        |
| `FullName`        | Text      | Yes      | Trimmed; 2-100 characters                           |
| `PhoneNumber`     | Text      | No       | Unique when present; normalized; never public       |
| `DateOfBirth`     | Date      | No       | Must be in the past; never public                   |
| `AvatarUrl`       | Text      | No       | Valid configured URL/path; maximum 2,048 characters |
| `Role`            | Enum      | Yes      | Exactly one of `ADMIN`, `LEARNER`, `TUTOR`          |
| `Status`          | Enum      | Yes      | `ACTIVE`, `LOCKED`, or `INACTIVE`                   |
| `LastLoginAt`     | Timestamp | No       | UTC                                                 |
| `CreatedAt`       | Timestamp | Yes      | UTC, immutable                                      |
| `UpdatedAt`       | Timestamp | Yes      | UTC                                                 |
| `DeletedAt`       | Timestamp | No       | Soft deletion; does not erase referenced history    |

### State rules

- Public registration creates only `LEARNER` or `TUTOR` in `ACTIVE` state.
- `LOCKED`, `INACTIVE`, or soft-deleted accounts cannot begin new sessions.
- Admin accounts are created only through controlled seed/administration paths.
- Changing a password updates the security stamp and invalidates prior authenticated sessions.

## AuthenticatedSession

Represents an issued browser session managed by the authentication framework.

| Field               | Type        | Required | Rules                                        |
| ------------------- | ----------- | -------- | -------------------------------------------- |
| `SessionId`         | UUID/string | Yes      | Unique, non-guessable identifier             |
| `UserId`            | UUID        | Yes      | References `UserAccount`                     |
| `IssuedAt`          | Timestamp   | Yes      | UTC                                          |
| `IdleExpiresAt`     | Timestamp   | Yes      | Re-evaluated within configured limits        |
| `AbsoluteExpiresAt` | Timestamp   | Yes      | Cannot exceed eight hours from issuance      |
| `RevokedAt`         | Timestamp   | No       | Set on logout or security-stamp invalidation |

### State rules

- A session is valid only when unexpired, unrevoked, and owned by an active account.
- Session identifiers and cookies are never logged or returned in JSON bodies.

## PasswordResetCredential

Represents a short-lived single-use recovery authorization.

| Field       | Type      | Required | Rules                                                    |
| ----------- | --------- | -------- | -------------------------------------------------------- |
| `Id`        | UUID      | Yes      | Primary key if persisted outside Identity token provider |
| `UserId`    | UUID      | Yes      | References `UserAccount`                                 |
| `TokenHash` | Text      | Yes      | Unique; raw credential is never persisted/logged         |
| `ExpiresAt` | Timestamp | Yes      | UTC and later than creation                              |
| `UsedAt`    | Timestamp | No       | Set exactly once after successful reset                  |
| `CreatedAt` | Timestamp | Yes      | UTC                                                      |

### State rules

- Only an unexpired credential with no `UsedAt` value can authorize reset.
- Successful use and password update occur atomically.
- A reset request does not reveal whether a credential was created.

## AuditEvent

Represents a security or administrative event without secret/private payloads.

| Field         | Type      | Required | Rules                                        |
| ------------- | --------- | -------- | -------------------------------------------- |
| `Id`          | UUID      | Yes      | Primary key                                  |
| `ActorUserId` | UUID      | No       | Null for anonymous attempts                  |
| `Action`      | Text/Enum | Yes      | Allowlisted event code                       |
| `EntityType`  | Text      | Yes      | Non-sensitive entity category                |
| `EntityId`    | Text      | No       | Identifier only; no object dump              |
| `IpAddress`   | Text      | No       | Retained only for configured security period |
| `CreatedAt`   | Timestamp | Yes      | UTC, immutable                               |

## Relationships and constraints

- `UserAccount` has zero or many sessions, reset credentials, and audit events.
- Unique normalized email and optional normalized phone constraints are enforced by the database.
- Account creation, role assignment, and profile creation run in one transaction.
- Password reset updates password, consumes the credential, and invalidates prior sessions in one
  transaction or one framework-supported atomic security flow.
